What's holding it back

Nothing is broken — it's just flat and busy. Everything competes for the same visual weight.

  • –Wall of 13+ icons in one undifferentiated row — the eye has no anchor.
  • –Primary transport reads the same as utilities. Play/pause barely stands out from CC or aspect.
  • –Thin, subtle glass (55% + 1px border) is easy to lose over bright video.
  • –Dimmed placeholders (◱ ♪ ⇄ …) look like the row is half-broken.
  • –Metadata + controls share one card, so the title fights the buttons for width.

Going glass · the whole app

One glass language, applied end to end

If the HUD goes glass, the rest of the app should speak the same material — otherwise the player looks like a different product. Below is the shared recipe, then every core component shown current → glass. Same tokens as the HUD: translucent white fill, hairline border, an inner top highlight, and the electric-blue focus glow from TvFocusable.

!

One honest caveat. True frosted blur only pays off where imagery sits behind it — the player, cards over posters, modals over video. The browse chrome (rail, category rows) sits on a solid dark page where blur has nothing to refract and just costs GPU. There, "glass" = a soft translucent surface (fill + highlight + glow), no heavy blur. And on the light theme, glass over the near-white page needs a stronger border to read — same rule the theme file already notes.

01Translucent fillwhite @ 5–7% (dark) — the surface itself is see-through.
02Hairline borderwhite @ 12–16% so the edge catches light.
03Inner top highlightinset 1px white @ 12% — the "lit glass" cue.
04Blur — only over mediabackdrop-blur 8–24px where there's something behind.
05Accent focus glow2px blue ring + soft bloom, matching the rest of the app.

Implementation spec · build sheet

Everything an implementer needs

Exact tokens, one shared modifier, and a per-component build table. The app already ships a translucent surfaceGlass + border pattern (see PlayerControls.kt) — this formalises it into a reusable helper and rolls it across the app. No real-time backdrop blur is required: the translucent fill is the glass (content behind shows through). backdrop-filter/RenderEffect is optional polish for modals only, gated on API 31+.

2 · One shared modifiernew file ui/theme/Glass.kt

The whole language is this one helper. A vertical gradient border (bright top → faint bottom) is the cheap, robust way to fake the inner top highlight — no drawWithContent maths, works on every API.

/** Glass surface: translucent fill + gradient hairline border (lit top edge).
 *  The fill alpha IS the glass — content behind shows through. No backdrop blur. */
fun Modifier.glassSurface(
    shape: Shape,
    elevated: Boolean = false,
): Modifier = composed {
    val c = AreIptvTheme.colors
    background(if (elevated) c.surfaceGlassElevated else c.surfaceGlass, shape)
        .border(
            width = 1.dp,
            brush = Brush.verticalGradient(listOf(c.glassHighlight, c.borderGlass)),
            shape = shape,
        )
        .clip(shape)
}

Focus is unchanged: keep composing TvFocusable / Modifier.tvFocusable (ui/theme/Focus.kt) outside glassSurface so the accent ring + glow still draws on top. Cross-fade any fill change with ui/theme/Motion.kt tokens (150–200ms).

4 · Blur policywhere real blur is worth it

The translucent fill alone reads as glass everywhere. Real backdrop blur is optional and only on surfaces with imagery behind them — apply it to dialogs and the player HUD only:

// API 31+ only; on ≤30 the translucent fill already carries the look.
val blurMod = if (Build.VERSION.SDK_INT >= 31)
    Modifier.graphicsLayer {
        renderEffect = RenderEffect
            .createBlurEffect(24f, 24f, Shader.TileMode.CLAMP)
            .asComposeRenderEffect()
    }
else Modifier

Rail, category rows, settings cards and tab strips sit over the solid dark page — no blur there (nothing to refract, wasted GPU). Do not blur the whole browse background.

5 · Light theme & a11ynon-negotiables

  • ✓Light glass over the near-white page needs the darker borderGlass edge (already in the token table) or the card vanishes.
  • ✓Keep body/label text on textPrimary/textSecondary — never hardcode white; on glass over bright video, add a 1-stop scrim under text if contrast drops below 4.5:1.
  • ✓Provider logos stay on the dark logoWell in both themes (unchanged rule).
  • ✓Every glass control still composes TvFocusable — nothing focusable without the accent ring.
  • ✓Honor reduced-motion for the fill cross-fade and any glow pulse.

My recommendation

Option B (Cinematic Unified) is the sweet spot: it delivers the "shinier, more modern" jump you're after while reusing the layout and D-pad focus model already in ArePlayerControls — lowest risk, biggest perceived polish per line changed. If you want to feel genuinely different from every other IPTV app, Option A (Floating Cluster) is the boldest and most distinctive, at the cost of reworking pod-to-pod focus. We can also blend — e.g. B's bar with A's centred accent-glow play disc.

On going fully glass: yes to a shared glass language, but apply blur only where media sits behind it (player, cards over posters, modals) and use soft translucent surfaces for the browse chrome. That keeps it fast on TV hardware and legible in the light theme — same result visually, without blurring panels that have nothing behind them.
